## 云推 HEX 双向编解码

`ble_calibration.cloud` 已实现：

- 解码 5 个基础解锁阈值和 5 个基础闭锁阈值。
- 解码源数据中存在的 `mstUnlock`、`quickLock`、`quickUnlock`、
  `mstThanSlave` 和 `bevelAngle`。
- 记录每个已知字段的原始字节或半字节位置。
- 修改阈值和已存在的策略字段。
- 编码时保留未知 TLV、保留位、未修改半字节及全部未修改字节。
- 不允许擅自新增源数据中不存在的策略，也不改变 TLV 长度。
- 无修改解码/编码结果与原始 HEX 逐字节一致。

命令行验证：

```bash
python3 run_app.py cloud-decode "00C2C7..."

python3 run_app.py cloud-encode "00C2C7..." \
  --unlock -63 -58 -55 -67 -64 \
  --lock -67 -61 -59 -70 -67 \
  --set quickLock.weakFront=2 \
  --set bevelAngle.offsetRFR=4
```

编码结果仍可由 `tools/parse_cloud.py` 解析。

## 策略引擎

`StrategyEngine` 输入一个方向的 `RssiSample` 序列和一组 `CloudParameters`，输出：

```text
condition.timestamp       实线时刻
condition.trigger_node    触发节点
condition.strategy        触发策略
condition.rssi            实线时刻 5 节点 RSSI
action.timestamp          虚线时刻
```

已实现：

- 基础闭锁：所有有效节点达到闭锁阈值并连续 2 秒。
- 基础解锁：任一有效节点达到解锁阈值并连续 0.5 秒。
- 主节点单独解锁。
- 快速闭锁。
- 快速解锁。
- 主节点强于从节点解锁。
- 斜角度补偿解锁。

所有稳定时间使用源时间戳差值，不依赖固定样本数量。阈值为 `0` 的节点或策略配置按
禁用处理；stale/无值节点不参与有效判定。

## 策略口径

- 快速闭锁将满足条件的缓冲区重新视为闭锁区，随后沿用 2 秒闭锁稳定时间。
- 快速解锁记录相邻从节点最强信号切换，并在 `unlockTime × 200 ms` 窗口内应用补偿。
- 主强从弱使用 `diff × 2 dB`。
- 斜角补偿只有在 `offset + 闭锁阈值 < 解锁阈值` 时有效。
- 多个解锁路径同时满足时，各路径独立连续计时，最先完成者触发。

这些口径来自 `tools/parse_cloud.py` 中的规则说明；第 10 步仍会用真实 ECU 的 `0x55A`
逐条建立黄金对比，发现差异时以实车实现修正。
