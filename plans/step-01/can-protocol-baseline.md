## 3. 报文定义

### 3.1 主节点 RSSI

| 字段 | 值 |
| --- | --- |
| CAN ID | `0x629` |
| 报文名称 | `IKM_MasterSt` |
| 长度 | 64 字节 |
| RSSI 位置 | `data[4]` |
| 解码 | `data[4] - 256` |

### 3.2 前、后节点 RSSI

| 字段 | 前节点 | 后节点 |
| --- | --- | --- |
| CAN ID | `0x62A` | `0x62A` |
| 报文名称 | `IKM_NodeABSt` | `IKM_NodeABSt` |
| 长度 | 64 字节 | 64 字节 |
| RSSI 位置 | `data[4]` | `data[28]` |
| 解码 | `data[4] - 256` | `data[28] - 256` |

### 3.3 左、右节点 RSSI

| 字段 | 左节点 | 右节点 |
| --- | --- | --- |
| CAN ID | `0x62B` | `0x62B` |
| 报文名称 | `IKM_NodeCDSt` | `IKM_NodeCDSt` |
| 长度 | 64 字节 | 64 字节 |
| RSSI 位置 | `data[4]` | `data[28]` |
| 解码 | `data[4] - 256` | `data[28] - 256` |

### 3.4 解闭锁请求

| 字段 | 值 |
| --- | --- |
| CAN ID | `0x55A` |
| 报文名称 | `BLE_Req_0x55A` |
| 长度 | 32 字节 |
| 信号位置 | `data[3]` 高四位 |
| 解码 | `(data[3] >> 4) & 0x0F` |
| `0` | 无解闭锁请求 |
| `1` | 实际解锁动作请求 |
| `2` | 实际闭锁动作请求 |

`1/2` 已确认为实测解闭锁动作与用户距离输入的时间锚点。

## 4. 输入验证

- `0x629` 长度必须大于 4。
- `0x62A` 和 `0x62B` 长度必须大于 28。
- `0x55A` 长度必须大于 3。
- 不相关 CAN ID 返回空解码结果。
- 长度不足的目标报文不产生业务数据，并记录诊断计数。
- RSSI 原始字节按当前脚本统一执行 `byte - 256`，不得由 Mock 使用不同规则。

## 5. 时间戳

每个原始帧保存：

```text
source_timestamp
receive_monotonic_time
arbitration_id
channel
is_fd
bitrate_switch
data
```

原则：

- 优先使用 CAN 设备提供的 `msg.timestamp` 建立相对时间轴。
- 同时记录本机 monotonic 接收时间，用于诊断设备时间戳回退或跳变。
- 每个方向以第一帧时间为相对时间零点。
- 策略持续时间按时间戳差值计算，不能按固定样本数量计算。

## 6. 五节点快照

`0x629`、`0x62A`、`0x62B` 到达时间不同。聚合器维护每个节点：

```text
value
last_source_timestamp
age_ms
is_stale
```

默认规则：

- 节点初次收到前为无效。
- 节点超过 stale 超时后不参与策略判定。
- stale 超时暂定为该报文实测周期的 3 倍。
- 未获得实车周期前，Mock 默认周期为 100 ms。

stale 的最终毫秒值在实车阶段确认，但算法和异常场景在 Mock 阶段实现。

## 7. 请求边沿

对 `lock_req` 维护上一个有效值：

- 非 `1` → `1`：记录一次解锁请求边沿。
- 非 `2` → `2`：记录一次闭锁请求边沿。
- 连续多个 `1` 或 `2` 只记录一次事件。
- `1/2` → `0`：清除活动请求，但不产生解闭锁事件。
- 报文长度错误时不改变上一个有效状态。

## 8. Mock 一致性

Mock 原始帧必须满足：

- 使用相同 CAN ID。
- 使用相同帧长度。
- 使用相同字节位置和 RSSI 编码。
- 使用相同请求边沿逻辑。
- 允许各 RSSI 报文使用轻微错开的时间戳，以验证聚合器。
- manifest 只用于提供测试预期，不能代替 CAN 解码结果。

## 9. 图表事件语义

- 实线：当前参数下，策略条件开始连续满足的时刻。
- 虚线：解闭锁动作时刻。
- 原始参数对应的实测虚线以 `0x55A` 请求为实际动作锚点。
- What-if 参数变化后，实线和虚线都由策略引擎重新计算并一起移动。
- 原始 `0x55A` 事件永久保存在原始数据中，图上不再增加第三类标线。
- 瞬时 RSSI、触发节点、触发策略以及 `闭(主)`/`解(前)` 标签取实线时刻的数据。
- 测试人员输入的实际闭锁和解锁距离分别绑定原始 `0x55A` 对应的虚线时刻。
- What-if 虚线移动后，根据相对原始虚线的时间差和步速计算当前动作距离。
- 优良差方向评级、优秀率及良/差列表使用当前动作距离同步重算。
