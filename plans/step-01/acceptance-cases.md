# 首版验收用例

文档状态：Frozen

版本：1.1

## 1. 协议和 Mock

### AC-001 CAN 字节解码

前置条件：

- 输入包含 `0x629`、`0x62A`、`0x62B`、`0x55A`。

验收：

- [ ] 能得到主、前、后、左、右 5 个 RSSI。
- [ ] `lock_req=1` 解码为解锁请求。
- [ ] `lock_req=2` 解码为闭锁请求。
- [ ] 不相关 CAN ID 返回空结果。
- [ ] 目标报文长度不足时不产生错误业务值。

### AC-002 八方向 Mock 数据

操作：

```bash
python3 tools/mock_can_generate.py --seed 20260730
```

验收：

- [ ] 生成 JSONL 和 manifest。
- [ ] manifest 包含 8 个固定方向。
- [ ] 每个方向包含闭锁请求、转身时刻和解锁请求。
- [ ] 每个方向闭锁早于转身，解锁晚于转身。
- [ ] 相同种子重复生成的原始帧完全一致。
- [ ] 生成过程不要求 `python-can`。

### AC-003 请求边沿去重

输入：

- 连续 5 帧 `lock_req=2`。
- 回到 `0`。
- 连续 5 帧 `lock_req=1`。

验收：

- [ ] 只产生 1 个闭锁事件。
- [ ] 只产生 1 个解锁事件。

## 2. 基础策略

### AC-004 基础闭锁

验收：

- [ ] 所有有效节点连续满足闭锁阈值 2 秒才产生动作。
- [ ] 1.99 秒时不产生动作。
- [ ] 中途任一节点退出闭锁区后重新计时。
- [ ] 阈值为 0 的节点不参与。
- [ ] 实线为本次连续满足的起点。
- [ ] 虚线为 2 秒完成时刻。

### AC-005 基础解锁

验收：

- [ ] 任一有效节点连续满足解锁阈值 0.5 秒才产生动作。
- [ ] 0.49 秒时不产生动作。
- [ ] 节点条件中断后该节点重新计时。
- [ ] 不同节点的持续时间不能错误累加。
- [ ] 阈值为 0 的节点不参与。
- [ ] 实线为触发节点连续满足的起点。
- [ ] 虚线为 0.5 秒完成时刻。

## 3. 附加策略

### AC-006 主节点单独解锁

- [ ] 根据信号最强节点选择 `mstUnlock[index]`。
- [ ] 主节点超过对应阈值时进入解锁判定。
- [ ] 配 0 的场景禁用。
- [ ] 500 ms 时限生效。
- [ ] 图表显示主节点触发和“主节点单独解锁”。

### AC-007 快速闭锁

- [ ] 只在缓冲区生效。
- [ ] weak offset 和 strong offset 按节点应用。
- [ ] 配 0 的节点不参与对应快速闭锁判定。
- [ ] 条件不满足时不应提前闭锁。
- [ ] 图表显示候选节点和“快速闭锁”。

### AC-008 快速解锁

- [ ] `unlockTime=0` 时策略禁用。
- [ ] 时间窗为 `unlockTime × 200 ms`。
- [ ] 只在相邻从节点区域切换后进入时间窗。
- [ ] 四个象限使用各自补偿字段。
- [ ] 图表显示对应象限的快速解锁策略。

### AC-009 主节点强于从节点

- [ ] `diff=0` 时策略禁用。
- [ ] 主节点必须是最强节点。
- [ ] 主节点至少比最强从节点强 `diff × 2 dB`。
- [ ] 图表显示主节点触发和“主强于从”。

### AC-010 斜角度补偿解锁

- [ ] 四个象限使用正确的两个节点和补偿字段。
- [ ] 全局启用前提不满足时策略禁用。
- [ ] 两个节点均满足补偿后阈值才触发。
- [ ] 图表显示瓶颈节点和对应斜角象限。

## 4. 云推 HEX

### AC-011 解码

- [ ] 解出 5 个基础闭锁阈值。
- [ ] 解出 5 个基础解锁阈值。
- [ ] 解出数据中存在的 5 套附加策略。
- [ ] 数据中不存在的策略显示为未包含且不可编辑。
- [ ] 非法十六进制、奇数字符和 TLV 越界有明确错误。

### AC-012 编码回写

- [ ] 修改基础阈值后写回正确字节。
- [ ] 修改 signed byte 和 nibble 字段后写回正确位置。
- [ ] 未修改字节保持不变。
- [ ] 编码结果可被 `tools/parse_cloud.py` 解析。
- [ ] 一键还原后重新编码得到本次解码的原始值。

## 5. 八方向图表

### AC-013 参数联动

- [ ] 修改任一基础阈值后 8 个方向全部重算。
- [ ] 修改任一附加策略后 8 个方向全部重算。
- [ ] 实线、虚线、瞬时 RSSI、触发节点和触发策略来自同次策略计算结果。
- [ ] 修改参数后实线和虚线一起移动。
- [ ] 原始 `0x55A` 事件仍保存在原始数据中，但图上不叠加第三类标线。
- [ ] 8 个方向的目标刷新时间不超过 200 ms。

### AC-014 信息显示

- [ ] 实线旁只显示 `闭(节点)` 或 `解(节点)`。
- [ ] 实线表示条件开始持续满足的时刻。
- [ ] 虚线表示解闭锁动作时刻。
- [ ] 图下显示条件时刻 5 节点瞬时 RSSI。
- [ ] 触发节点有明确标识。
- [ ] 每个方向显示触发策略。

### AC-015 距离评级

- [ ] 闭锁和解锁使用各自的优、良、差区间。
- [ ] 图表背景颜色有足够区分度。
- [ ] 统计列出良和差的方向。
- [ ] 两个实际距离分别绑定原始 `0x55A` 解闭锁虚线时刻。
- [ ] 原始参数下，评级距离等于用户输入的实际距离。
- [ ] What-if 虚线移动后，按新旧虚线时间差和步速计算当前闭锁、解锁距离。
- [ ] 参数变化后，方向评级、优秀率和良/差方向列表同步重算。
- [ ] 闭锁优秀率以已输入实际闭锁距离的方向数为分母。
- [ ] 解锁优秀率以已输入实际解锁距离的方向数为分母。
- [ ] 当前参数未触发动作时仍计入对应分母，并显示为 `差（未触发）`。
- [ ] 对应分母为零时显示 `--`。

## 6. 会话与项目

### AC-016 单方向会话

- [ ] 用户可以选择方向并开始记录。
- [ ] 可以观察等待闭锁、等待解锁和完成状态。
- [ ] 可以输入闭锁和解锁距离。
- [ ] 可以重录当前方向。
- [ ] 闭锁和解锁事件齐全时自动完成当前方向。
- [ ] 缺少任一事件时可以手动结束并保存为“不完整方向”。

### AC-017 保存与回放

- [ ] 项目保存原始数据引用、方向、距离、步速和参数。
- [ ] 重新打开后结果与保存前一致。
- [ ] 没有 CAN 设备也可以修改参数并重算。
- [ ] Mock JSONL 和 BLF 使用同一回放接口。

## 7. Windows 交付

### AC-018 Mock 打包验收

- [ ] Windows 10/11 干净系统不安装 Python也能运行。
- [ ] 安装包包含 `python-can==4.6.1`、`zlgcan==0.3.0` 和兼容的 `clgcan_driver.pyd`。
- [ ] 能生成或加载 Mock 数据。
- [ ] 能完成八方向展示、参数修改、保存和重开。
- [ ] Mock 连续循环运行 2 小时无崩溃。

### AC-019 实车验收

- [ ] 安装包能加载 ZLG library 并连接设备。
- [ ] 能读取四类目标报文。
- [ ] 设备断开后应用可恢复或明确提示。
- [ ] 能完成一轮八方向实车测试。
- [ ] 2 小时连续实车采集无崩溃。

AC-019 在 Windows 包完成后执行，不阻塞前面的软件开发。
