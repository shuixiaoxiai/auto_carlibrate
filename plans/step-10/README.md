# 第十步：CAN 盒、实车联调和正式发布

状态：**进行中**

开始日期：2026-07-31

## 已完成的软件接入

- 桌面应用新增 ZLG 设备区，可配置设备类型、设备索引、CAN 通道、仲裁域/数据域
  波特率、终端电阻和 library 路径。
- 配置保存到用户数据目录；library 路径留空时使用 `zlgcan` 包的默认查找逻辑。
- `ZlgCanSource` 使用与 `tools/can_read_save.py` 相同的 `python-can + zlgcan` 打开方式，
  并沿用 `ZCAN_USBCANFD_200U`、500 kbit/s、2 Mbit/s 和终端电阻默认值。
- 真实数据源使用独立接收线程。设备连接一次后跨 8 个方向保持在线，空闲帧不进入方向
  数据；每个方向只记录从“开始记录”到“手动结束”的帧。
- 实车方向原始数据默认写入 BLF；每个方向独立文件，记录结束会立即关闭 writer。
- 连接失败会显示错误，失败的接收线程清理后可直接重新连接，无需重启应用。
- 缺少闭锁或解锁事件时仍支持手动结束，并保留已有事件、距离和 RSSI 数据。
- Windows 冻结应用默认无参数进入 ZLG 实车工作区。

## 无硬件自动验收

```bash
python tools/live_ui_smoke.py --width 1100 --height 720
```

该测试使用可推送原始 `CanFrame` 的模拟实时源，但走正式持久连接、正式协议解码、正式
方向会话和正式桌面控件路径，完成：

```text
连接一次设备
  → 逐方向开始记录
  → 接收原始 RSSI / 0x55A 帧
  → 输入实际闭锁、解锁距离
  → 手动结束方向
  → 共完成 8 个方向
  → 保存项目
  → 断开一次设备
```

当前验收结果：

- [x] 8/8 方向完成，闭锁和解锁汇总分母均为 8。
- [x] 设备只连接一次并在最后断开一次。
- [x] 方向之间保持连接，不把空闲帧写入下一方向。
- [x] 设备配置可保存和重新读取。
- [x] 8 个方向分别生成原始数据文件。
- [x] 连接失败后可替换数据源并重新连接。
- [x] 阈值、策略、8 图和闭锁/解锁优良差汇总仍通过 200 ms 门禁。
