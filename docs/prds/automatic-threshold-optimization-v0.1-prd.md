## 1. 背景与目标

当前应用已经能够基于完整方向 RSSI 序列执行 What-if 重算，展示解闭锁时刻、触发节点、
动作距离和优良差评级。下一阶段希望在现有回放能力上增加自动阈值推荐：程序自动搜索一组
5 节点解锁阈值和 5 节点闭锁阈值，使尽可能多的方向或“方向 + 组”样本落入优秀距离区间。

目标用户：BLE 数字钥匙标定工程师和实车测试人员。

核心目标：

- 自动给出一组满足硬约束的 10 个基础阈值。
- 尽量增加闭锁优秀样本数和解锁优秀样本数。
- 避免为了改善单个方向而让其他方向明显恶化。
- 给出可解释的预测结果、未改善方向和参数变化量。
- 推荐只进入 What-if 预览，不自动写车或刷写云推参数。

## 2. 首版范围

### 2.1 包含

- 使用已保存的原始方向 RSSI 序列和现有策略引擎做离线重放。
- 搜索主、前、后、左、右 5 个节点的解锁与闭锁基础阈值。
- 应用解闭锁阈值差、合法范围和方向—节点关系约束。
- 对候选参数计算事件时刻、触发节点、当前动作距离和优良差评级。
- 输出一组主推荐参数及其预测效果；允许保留若干同分备选用于解释。
- 兼容每方向最多三组原始数据；均值曲线不作为优化器输入。

### 2.2 不包含

- 自动写入车辆或自动刷写云推参数。
- 自动修改或开启附加策略。
- 使用均值 RSSI 曲线代替原始组数据执行策略判定。
- 自动测量真实距离或自动修正步速误差。
- 声称离线预测可以替代新一轮实车验证。

现有应用已经支持手动编辑附加策略；本优化器首版固定使用当前策略值，只搜索基础阈值。

## 3. 输入与输出

### 3.1 必需输入

每个有效“方向 + 组”至少需要：

- 完整远离和靠近过程的 5 节点 RSSI 时间序列。
- 与实车逻辑一致的时间戳、节点有效性、滤波值和 stale 处理结果。
- `0x55A` 实车闭锁、解锁动作时刻。
- 测试人员输入的实测闭锁距离和实测解锁距离。
- 该组步速。
- 当前 5 节点解锁阈值、5 节点闭锁阈值和当前附加策略。
- 当前策略引擎和距离计算版本。

缺少某类实测距离的样本不进入该类优化目标。具有实测距离但候选参数未计算出动作的样本
计为差（未触发）。

### 3.2 推荐输出

主推荐至少包括：

- 5 节点当前闭锁阈值、推荐闭锁阈值和变化量。
- 5 节点当前解锁阈值、推荐解锁阈值和变化量。
- 每个节点推荐后的解闭锁阈值差。
- 当前与推荐参数下的闭锁优秀率、良/差/未触发明细。
- 当前与推荐参数下的解锁优秀率、良/差/未触发明细。
- 每个方向或“方向 + 组”的预测动作距离、等级和触发节点变化。
- 仍未进入优秀区间的样本、原因和距离优秀区间还差多少。
- 优化停止原因、搜索范围、评估候选数和计算版本。

如果多组参数拥有相同主目标，程序可以同时保留：

- 主推荐：按完整排序规则选择的唯一结果。
- 保守备选：与当前参数改动最小。
- 稳健备选：对阈值 `±1 dB` 扰动最不敏感。

## 4. 已确认业务规则

### 4.1 基础闭锁规则

- 所有有效节点达到各自闭锁阈值并连续保持 2 秒后产生闭锁动作。
- 阈值为 `0` 的节点不参与判定。
- 候选参数必须复用正式 `StrategyEngine`，不得另写一套近似判断逻辑。

### 4.2 基础解锁规则

- 任一有效节点达到其解锁阈值并连续保持 0.5 秒后产生解锁动作。
- 阈值为 `0` 的节点不参与判定。
- 多个路径同时满足时，使用正式策略引擎的最先完成结果。

### 4.3 What-if 距离

候选动作距离沿用当前已冻结公式：

```text
闭锁当前距离 = 实测闭锁距离 + 步速 × (候选闭锁时刻 - 实测闭锁时刻)
解锁当前距离 = 实测解锁距离 - 步速 × (候选解锁时刻 - 实测解锁时刻)
```

### 4.4 距离等级

闭锁：

- 优：`8 <= 距离 <= 12` m。
- 良：`5 <= 距离 < 8` m 或 `12 < 距离 <= 16` m。
- 差：`距离 < 5` m、`距离 > 16` m 或未触发。

解锁：

- 优：`2 <= 距离 <= 5` m。
- 良：`0.5 <= 距离 < 2` m 或 `5 < 距离 <= 8` m。
- 差：`距离 < 0.5` m、`距离 > 8` m 或未触发。

## 5. 阈值约束

对节点 `i` 定义：

```text
L_i = 闭锁阈值
U_i = 解锁阈值
```

### 5.1 硬约束：解闭锁阈值差

每个节点必须满足：

```text
U_i - L_i > 3 dB
```

当阈值步长为整数 `1 dB` 时等价于：

```text
U_i - L_i >= 4 dB
```

任何不满足该条件的候选参数不得进入策略重放和评分阶段。

### 5.2 软目标：主节点阈值差

主节点的解闭锁阈值差应在不降低核心优良差结果的前提下尽可能大：

```text
G_main = U_main - L_main
```

建议将 `G_main` 作为质量目标之后的次级排序项，而不是第一目标。否则优化器会倾向于将主节点
闭锁和解锁阈值推到搜索边界。

### 5.3 待配置硬约束

实现前必须确定：

- 每个节点解锁阈值的合法最小值、最大值和步长。
- 每个节点闭锁阈值的合法最小值、最大值和步长。
- 阈值 `0`（禁用）是否允许由优化器主动生成。
- 主节点阈值差是否还有目标下限或最大允许值。
- 单次推荐相对当前值允许变化的最大 dB 数。

## 6. 方向—节点关系

方向优化时只主动搜索主要相关节点：

| 方向 | 主动搜索节点 |
| --- | --- |
| 正前 | 主、前 |
| 右前 | 主、前、右 |
| 正右 | 主、右 |
| 右后 | 主、右、后 |
| 正后 | 主、后 |
| 左后 | 主、左、后 |
| 正左 | 主、左 |
| 左前 | 主、左、前 |

该表定义搜索变量范围，不等于从重放中删除其他节点：

- 优化左前时，只改变主、左、前三个节点的参数对。
- 后、右节点阈值保持不变。
- 正式重放仍保留全部 5 节点，以遵守闭锁 AND 和解锁 OR 规则。
- 候选参数仍需检查所有受改动节点影响的方向，防止局部改善造成全局回退。
- 修改主节点时默认认为 8 个方向都受影响。

建议以物理关系表作为初始影响矩阵，并通过日志灵敏度扫描验证：分别扰动每个节点阈值
`±1/±2/±3 dB`，记录各方向动作距离变化、触发节点切换和是否未触发。数据验证后的影响矩阵
用于选择搜索变量、识别受影响方向和复用未受影响结果缓存。

## 7. 优化目标与排序

首版建议使用字典序，而不是难以解释的单一加权总分。候选参数按以下顺序比较：

1. 优秀样本数量最多。
2. 差和未触发样本数量最少。
3. 良样本到最近优秀区间边界的总距离最小。
4. 最差样本到优秀区间的距离最小，避免严重牺牲单个方向。
5. 主节点解闭锁阈值差 `G_main` 尽可能大。
6. 全部阈值相对当前参数的总变化量最小。
7. 改动节点数量最少。
8. 对所有阈值 `±1 dB` 扰动后结果最稳定。

闭锁和解锁样本默认等权。由于 `U_i - L_i >= 4 dB` 将两类阈值耦合，不能再把闭锁和解锁
完全独立优化。

待确认：如果闭锁和解锁目标发生冲突，是按总优秀样本数排序，还是要求两者各自达到最低
优秀率后再比较总数。

## 8. 推荐搜索方案

目标函数具有平台、跳变、触发节点切换和未触发状态，不适合使用梯度下降。首版建议使用
受约束的方向分块束搜索。

### 8.1 候选生成

从当前参数开始，对当前待改善方向的主动节点生成参数对邻域：

```text
delta_lock   in {-1, 0, +1} dB
delta_unlock in {-1, 0, +1} dB
```

生成后立即过滤非法范围、禁用规则和 `U_i - L_i < 4 dB` 的组合。

以左前为例，只组合主、左、前三个节点。其他节点保持当前值。搜索可以逐轮扩展到
`±2/±3/... dB`，不在第一轮直接穷举全部 10 维空间。

### 8.2 候选评价

对每个合法候选：

1. 只调度受改动节点影响的原始“方向 + 组”数据。
2. 使用全部 5 节点序列和正式策略引擎重放。
3. 计算候选动作距离、触发节点和优良差。
4. 与未受影响方向的缓存结果合并。
5. 按第 7 节字典序评分。
6. 记录候选相对当前结果的改善和回退方向。

### 8.3 束搜索与迭代

- 每轮只保留排序最高的前 `K` 组候选；`K` 是可配置性能参数。
- 从当前最差或距离优秀区间最远的方向开始分块搜索。
- 只有全局排序变好时才接受新的基准参数。
- 接受后重新计算最差方向和影响矩阵状态。
- 所有方向局部搜索结束后，执行一次全节点 `±1 dB` 联合校验，降低局部最优风险。
- 搜索过程必须可取消，不能阻塞采集线程和 UI 主线程。

示意伪代码：

```text
best = current_parameters

while not plateau:
    target = select_worst_direction(best)
    active_nodes = influence_matrix[target]
    candidates = generate_feasible_neighbors(best, active_nodes)
    evaluated = replay_affected_datasets(candidates)
    next_best = lexicographic_best(evaluated)

    if next_best is not better than best:
        mark_direction_plateau(target)
    else:
        best = next_best

best = global_plus_minus_one_validation(best)
return best
```

## 9. 多组数据与稳健性

- 每个原始“方向 + 组”作为独立重放样本。
- 均值 RSSI 曲线只用于展示，不进入优化器。
- 优化结果必须列出到“方向 · 第 N 组”，避免掩盖同方向不同组的波动。
- 单组数据也可以运行优化，但结果必须标记为低置信度。
- 推荐使用每方向三组数据进行训练和验证，防止只适配某一次 RSSI 抖动。
- 推荐参数必须额外执行 `±1 dB` 邻域稳定性检查。

待确认的多组评分口径：

- 直接最大化全部有效“方向 + 组”优秀样本数；或
- 先聚合为方向级结果，例如至少 `2/3` 组优秀才认为该方向优秀。

首版实现前必须冻结其中一种口径。无论采用哪一种，都不得把均值曲线作为新的策略输入样本。

## 10. 阈值优化平台与策略扩展

### 10.1 平台判定

同时满足以下条件时，可以判断阈值搜索达到当前上限：

- 所有合法单节点 `±1 dB` 改动均不能提升全局排序。
- 所有方向的相关节点局部联合搜索均不能提升全局排序。
- 搜索扩大到配置范围后，最优结果连续若干轮不再变化。
- 改善剩余差/良方向必然导致其他方向降级，形成明确冲突。
- 全节点 `±1 dB` 联合校验没有找到更优候选。

程序应输出“阈值优化已达到上限”、当前可达到的优良差结果、冲突方向和停止原因。

### 10.2 后续策略优化

首版不自动开启或修改策略。后续按以下顺序扩展：

```text
基础阈值搜索
    -> 达到平台
    -> 允许启用一个已注册策略
    -> 在该策略状态下重新优化基础阈值
    -> 比较净改善
    -> 必要时再增加下一个策略
```

每个策略扩展至少声明：

- 策略标识、开关和新增参数范围。
- 影响闭锁、解锁还是两者。
- 影响方向和节点。
- 合法性约束和与其他策略的冲突。
- 正式策略引擎中的重放入口。
- 启用成本和排序优先级。

优化目标应加入策略复杂度约束，保证基础阈值能够解决时不自动开启附加策略。

## 11. 性能与缓存建议

- 预计算每个节点、候选阈值对应的条件布尔序列或有效时间区间。
- 对闭锁使用 5 节点条件序列的交集和 2 秒连续区间检测。
- 对解锁分别计算节点 0.5 秒连续区间，再选择最先完成路径。
- 按“参数版本 + 方向 + 组 + 数据版本 + 策略版本”缓存重放结果。
- 利用影响矩阵跳过确定未受本轮参数变化影响的数据集。
- 优化运行在线程池或独立任务中；UI 只接收进度和候选快照。
- 相同输入、参数、搜索配置和计算版本必须产生相同推荐结果。

性能目标需要在确定阈值范围、步长、束宽 `K` 和最大 24 份数据后通过基准测试冻结。

## 12. 可信度边界与风险

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| 候选动作晚于实车动作后，BLE 状态或采样方式已经变化 | 反事实序列可能不可信 | 标定模式持续保留一致 RSSI；标记超出可信回放区间的候选 |
| 使用原始 RSSI 而 ECU 使用不同滤波值 | 推荐与实车不一致 | 复用正式处理链并建立 `0x55A` 黄金用例 |
| 单方向单组数据波动 | 过拟合一次试验 | 使用多组原始数据和邻域稳定性检查 |
| 方向—节点关系过度简化 | 漏掉远端节点异常影响 | 主动搜索节点裁剪，正式重放保留全部节点；用灵敏度扫描修正矩阵 |
| 最大化主节点阈值差导致参数走向边界 | 鲁棒性下降 | 设置合法范围；将主节点差值置于质量目标之后 |
| 局部搜索陷入局部最优 | 推荐不是全局最好 | 束搜索、多起点和最终全节点 `±1 dB` 校验 |
| 自动启用策略导致配置复杂化 | 难以解释和验证 | 首版固定策略；未来逐个注册并惩罚复杂度 |

## 13. 未来实现验收标准

- [ ] 所有推荐节点均满足 `U_i - L_i >= 4 dB`。
- [ ] 推荐阈值均满足节点合法范围、步长和禁用规则。
- [ ] 推荐候选使用正式策略引擎和全部 5 节点重放。
- [ ] 修改局部方向相关节点时，所有受影响方向和组均被重新评价。
- [ ] 主推荐按冻结后的字典序确定，相同输入重复运行结果一致。
- [ ] 输出闭锁和解锁当前/推荐优秀率、良/差/未触发明细。
- [ ] 输出推荐前后 10 个阈值、每节点阈值差和触发节点变化。
- [ ] 未触发样本计为差，并明确显示停止原因。
- [ ] 多组原始数据独立参与评分，均值曲线不作为优化输入。
- [ ] 一键应用只更新 What-if 参数，不自动写车。
- [ ] 达到阈值优化平台时给出上限和冲突方向，不擅自启用策略。
- [ ] 所有阈值 `±1 dB` 邻域稳定性检查结果可查看。
- [ ] 自动优化任务可取消，且不阻塞采集或 UI 主线程。

## 15. 实施前建议顺序

1. 冻结 O-001～O-005，并准备覆盖优、良、差和未触发的确定性 Mock 数据。
2. 为正式 `StrategyEngine` 增加批量候选重放基准测试。
3. 实现约束模型、字典序评分和方向—节点影响矩阵。
4. 实现阈值邻域生成、方向分块束搜索、缓存和取消。
5. 增加推荐结果解释与“应用到 What-if”交互。
