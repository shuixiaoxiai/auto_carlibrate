# 多组方向数据 - 产品需求文档（PRD）

## 需求说明

### 背景

- **业务问题**：当前每个方向只能保存一份采集数据，重复测试会覆盖旧记录，无法比较同一方向的重复测试结果，也无法通过均值降低单次采集波动。
- **目标用户**：执行 BLE 数字钥匙八方向实车标定、阈值验证和策略分析的测试人员与软件工程师。
- **价值主张**：在不增加手动组管理负担的前提下，为每个方向保留固定三组数据，支持独立查看、统一重算、总体统计和平均趋势分析。

### 功能概览

- 每个方向固定支持第一组、第二组、第三组三个数据槽位。
- 采集时自动选择目标组，不在采集栏增加“当前组”或“新增组”控件。
- 每个方向图可以独立切换三组数据和均值视图，默认显示最近采集成功的一组。
- 阈值或策略变化时，所有方向、所有组和均值视图同步重算。
- 顶部统计始终汇总全部方向、全部有效组，均值结果不重复计入统计。
- 每组保存独立的闭锁实测、解锁实测和步速，并支持删除。
- 项目保存一个默认步速，新采集优先使用该值，单组可单独调整。
- 均值视图绘制平均 RSSI 曲线，并展示聚合后的实测数据与策略结果。

### 功能边界

本期包含：

- 固定三组数据的采集、替换、删除、保存、恢复和回放。
- 三组图表独立切换、最近组默认选择、均值 RSSI 曲线。
- 全部组的阈值与策略重算、顶部聚合统计。
- 旧项目和旧采集文件的兼容迁移。

本期不包含：

- 超过三组或用户自定义组名。
- 八张图之间的组选择联动。
- 在采集栏手动指定目标组。
- 将平均 RSSI 曲线重新输入策略引擎进行判定。
- 自动推荐阈值、自动清理未引用原始采集文件。

### 用户场景

1. 测试人员选择“前方”并开始采集；系统发现没有数据，自动写入第一组。
2. 第二、三次采集同一方向时，系统依次写入第二组和第三组。
3. 三组均存在时再次采集，系统不询问确认；采集成功后自动替换第三组。
4. 用户删除前方第二组后再次采集前方，系统自动补入第二组。
5. 用户分别将八张图停留在不同组，顶部仍统计所有方向的所有有效组。
6. 用户调整阈值或策略，三组的事件、距离、评级、均值和顶部统计一起更新。

## 详细需求

### 输入与输出

输入包括：

- 方向：八个固定方向之一。
- 采集产生的 RSSI 样本和车辆解闭锁事件。
- 每组闭锁实测距离、解锁实测距离、步速。
- 项目默认步速。
- 当前阈值和附加策略参数。

输出包括：

- 每个方向三组独立的 RSSI 曲线、条件线、动作线、距离和评级。
- 每个方向的平均 RSSI 曲线和聚合结果。
- 汇总全部有效“方向 + 组”样本的闭锁、解锁优良差统计。
- 可保存、恢复和离线回放的项目数据。

### 自动组分配

目标组按以下确定性规则选择：

| 已占用组 | 下一次采集目标 |
| --- | --- |
| 无 | 第一组 |
| 第一组 | 第二组 |
| 第一、二组 | 第三组 |
| 第一、三组 | 第二组 |
| 第二、三组 | 第一组 |
| 第一、二、三组 | 第三组，成功后无确认覆盖 |

通用规则：

1. 存在空位时，选择编号最小的空位。
2. 三组均存在时，目标固定为第三组。
3. 开始采集时不得提前删除目标组旧数据。
4. 新采集成功并手动结束后，原子替换目标组。
5. 采集失败、中止或未完成替换时，原目标组继续保留。

### 图表交互

- 每个方向图标题区域在“闭锁实测”前显示“第一组、第二组、第三组、均值”。
- 四个选择项固定显示；空组不可选并表现为禁用状态。
- 八个方向图的选择状态相互独立。
- 新采集完成后，该方向图切换到刚保存的目标组。
- 项目重新打开时，选择 `recorded_at` 最大的组；时间相同则选择组号较大的组。
- 删除当前组后，选择剩余组中 `recorded_at` 最大的一组；没有剩余组时显示“未记录”。
- 均值视图中的闭锁实测、解锁实测和步速只读，并标注参与均值的有效组数。
- “删除当前组”在均值视图和空组状态下禁用。

### 默认步速与组步速

- 项目保存 `default_walking_speed_mps`，初始默认值为 `1.0 m/s`。
- 允许范围沿用当前步速输入范围：`0.1～5.0 m/s`。
- 每次开始新采集前，“本次步速”初始化为项目默认步速。
- 用户可在开始采集前修改本次步速，采集完成后将其保存到目标组。
- 每组步速可在对应组图表中单独编辑。
- 修改某组步速只重算该组、该方向的均值和顶部统计。
- 修改项目默认步速只影响后续采集，不修改已有组数据。

### 删除

- 删除对象是当前方向图中当前选择的单组数据。
- 删除前显示方向和组号并要求确认。
- 删除后立即从图表、均值和顶部统计中移除。
- 被删除的组号成为空位，后续采集优先补入该空位。
- 删除只解除项目数据关联，不物理删除原始采集文件；未引用文件清理不在本期范围内。

### 顶部统计

- 顶部统计始终聚合全部方向、全部有效组，最多包含 24 个样本。
- 每个“方向 + 组”记录是一个独立统计样本。
- 闭锁分母为已填写闭锁实测距离的样本数；解锁分母独立计算。
- 当前参数下未触发但具有对应实测距离的样本计为差。
- 统计明细使用“方向 · 第 N 组”标识，例如“前方 · 第 2 组（未触发）”。
- 均值是派生展示结果，不纳入顶部统计，避免重复计数。
- 添加、替换、删除组数据，编辑组距离或步速，以及修改阈值或策略后，统计必须同步刷新。

### 均值 RSSI 曲线

- 均值按单个方向计算，只使用该方向当前存在且包含样本的组。
- 每组样本先转换为相对采集时间：`sample.source_timestamp - record.start_timestamp`。
- 使用现有处理采样周期作为目标时间网格；当前默认采样率为 10 Hz，即 0.1 秒。
- 平均曲线覆盖所有参与组共同拥有的时间区间，终点为参与组最短有效时长。
- 每个节点独立插值和求算术平均；无效或缺失节点值不参与该时间点平均。
- 某时间点没有任何有效节点值时，该节点在平均曲线上保留为空值，不补零。
- 只有一组有效数据时，均值曲线与该组曲线一致。
- 没有有效样本时，均值选项禁用。
- 平均曲线只用于展示，不作为策略引擎输入。

### 均值结果

- 三组仍分别使用原始 RSSI 样本执行当前阈值和策略分析。
- 闭锁、解锁条件时刻和动作时刻先转为相对采集时间，再对已触发组求算术平均。
- 预测距离、闭锁实测、解锁实测和步速分别对具有对应有效值的组求算术平均。
- 均值视图显示“有效结果数 / 现有组数”；未触发组不参与对应事件时刻和预测距离平均。
- 均值评级根据均值预测距离使用现有距离评级规则计算。
- 均值结果不写入顶部统计，也不覆盖任何原始组结果。

### 数据要求

每份方向记录至少新增：

- `group_index`：整数，范围 `1～3`。
- `recording_id`：每次成功采集唯一的 UUID。
- `recorded_at`：采集成功完成时间，用于确定默认展示组。

项目新增：

- `default_walking_speed_mps`：有限浮点数，范围 `0.1～5.0`。

项目内唯一性规则调整为：

```text
project_id + direction + group_index
```

### 边界和异常处理

- 覆盖第三组时不弹确认框，但只有新采集成功后才替换旧数据。
- 如果新原始文件创建失败，不改变现有组状态。
- 删除当前显示组时，尚未提交的该组距离或步速编辑必须先完成或取消。
- 记录缺少开始时间但样本非空时，回放继续按错误处理，不生成不可信均值。
- 某组只有部分节点有效时，按节点独立生成均值曲线。
- 某组没有实测距离时仍可显示 RSSI 和策略事件，但不进入对应顶部统计分母。
- 项目打开后某个原始文件缺失时，应指出具体“方向 + 组”，其他可恢复组不得丢失。

## 设计决策

### 技术方案

- **架构选择**：保留现有单组八方向计算服务，在 UI 状态层增加固定三组调度和聚合层。
- **组计算**：按 `group_index` 将数据分成三批，每批最多八个方向，分别调用现有八方向重算服务。
- **结果结构**：使用 `group_results[group_index].directions[direction]` 保存单组结果，再产生顶部总统计和 `mean_results[direction]`。
- **状态索引**：UI 数据访问由单一 `direction` 键升级为 `(direction, group_index)`。
- **异步刷新**：阈值或策略改变时批量重算三组；只重绘八张图当前选择的视图，均值曲线按方向缓存。

### 关键组件

- 领域模型：支持固定组三元索引、采集 ID、采集完成时间和项目默认步速。
- UI 状态：支持按方向和组查询、自动分配、原子替换、删除、最近组选择和均值缓存。
- 重算聚合：调度三次八方向计算，聚合 24 份样本统计和每方向均值。
- 图表卡片：四状态独立切换、平均曲线、只读均值指标和单组删除。
- 项目工作区：生成不会互相覆盖的组采集路径。
- 存储与回放：保存复合键并兼容旧项目。

### 数据存储

- SQLite 数据库版本升级为 v2。
- 方向记录表主键升级为 `(project_id, direction, group_index)`。
- 项目表增加默认步速字段，或在项目元数据中持久化等价字段。
- 新采集文件建议使用：

```text
captures/<project-id>/<direction>/group-<index>/<recording-id>.jsonl
captures/<project-id>/<direction>/group-<index>/<recording-id>.blf
```

- 旧数据库迁移时，全部原方向记录设置为第一组，生成稳定的 `recording_id`，并以原记录时间或迁移时间补充 `recorded_at`。
- 旧原始文件保持原位置，迁移不得强制移动或重写。
- 恢复快照、分析历史和项目列表同步支持新结构；项目列表同时区分已采集方向数和记录总数。

### 界面接口

- `dataset_for(direction, group_index)`：读取指定组。
- `latest_group_for(direction)`：按 `recorded_at` 读取最近组。
- `next_capture_group(direction)`：返回最小空位，否则返回第三组。
- `upsert_dataset(direction, group_index, dataset)`：采集成功后原子新增或替换。
- `remove_dataset(direction, group_index)`：删除单组。
- `update_measurements(direction, group_index, ...)`：修改单组距离和步速。
- `mean_for(direction)`：读取缓存的平均曲线和聚合结果。

### 约束

- **性能**：最大 24 份数据时，参数变化后的核心重算目标不超过 600 ms，完整界面刷新目标不超过 1 秒；组切换使用缓存，目标响应不超过 100 ms。
- **兼容性**：必须支持现有项目数据库、JSONL、BLF、恢复快照和 Windows 打包流程。
- **数据安全**：无确认覆盖第三组不得提前破坏旧数据；新数据完整保存后才能替换数据库引用。
- **可扩展性**：本期代码可使用常量限制三组，但复合键和结果结构不得把组号编码进字段名，避免未来扩组时再次迁移全部逻辑。

### 风险评估

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| 不同组采集时长导致均值曲线失真 | 中 | 使用相对时间和共同有效区间；明确均值曲线只作展示 |
| 三组同步重算阻塞 UI | 高 | 限帧、缓存均值曲线，必要时将批量重算移出 UI 主线程 |
| 无确认覆盖造成旧数据丢失 | 高 | 采集成功后原子换引用，旧文件暂不物理删除 |
| 数据库迁移破坏旧项目 | 高 | 增加 v1 到 v2 迁移测试并保留旧采集路径 |
| 统计中重复方向难以辨认 | 中 | 明细统一显示“方向 · 第 N 组” |
| 组删除后默认选择混乱 | 低 | 完全按 `recorded_at` 决定最近组，时间相同时使用组号兜底 |

## 验收标准

### 功能验收

- [ ] 同一方向连续采集三次，数据依次进入第一、第二、第三组。
- [ ] 三组已满时再次采集，不弹确认；成功结束后仅第三组被替换。
- [ ] 三组已满时新采集失败，原第三组数据和文件引用保持不变。
- [ ] 删除第二组后再次采集，数据自动进入第二组。
- [ ] 删除第二组并重新采集后，该方向图默认停留在最新采集的第二组。
- [ ] 八张图可以分别停留在不同组，互不切换。
- [ ] 每张图可显示第一、第二、第三组和平均 RSSI 曲线。
- [ ] 修改阈值或策略后，全部现有组、均值和顶部统计同步更新。
- [ ] 顶部统计最多统计 24 份“方向 + 组”数据，且不重复计入均值。
- [ ] 统计明细能够区分同一方向的不同组。
- [ ] 新采集默认使用项目默认步速，单次和已有组步速均可独立修改。
- [ ] 修改默认步速不会改变已有组步速。
- [ ] 删除单组后，该组从图表、均值和统计中消失，其他组不受影响。
- [ ] 旧项目打开后原数据出现在第一组，计算结果与迁移前一致。

### 质量标准

- [ ] 领域模型、自动分配、最近组、均值、统计和迁移规则均有单元测试。
- [ ] JSONL 与 BLF 多组保存、关闭、重开和回放结果一致。
- [ ] 覆盖与失败恢复测试证明旧第三组不会被提前破坏。
- [ ] 24 份参考数据下核心重算不超过 600 ms，界面完整刷新不超过 1 秒。
- [ ] 组切换不触发全量策略重算，缓存命中时响应不超过 100 ms。
- [ ] 现有单组策略、距离评级、项目保存和 Windows 构建测试无回归。

### 用户验收

- [ ] 用户无需选择组即可连续完成重复采集。
- [ ] 用户能够从按钮状态判断哪些组存在、当前显示哪一组。
- [ ] 均值视图明确显示参与组数，并标明平均曲线不直接参与策略判定。
- [ ] 覆盖第三组、补空位和删除后的行为与本文档一致。
- [ ] 使用说明补充多组、默认步速、均值和删除操作。

## 执行阶段

### 阶段 1：数据模型与迁移

**目标**：建立固定三组的持久化基础并保证旧项目兼容。

- [ ] 增加组号、采集 ID、采集完成时间和项目默认步速。
- [ ] 升级 SQLite 表结构、恢复快照和分析序列化。
- [ ] 实现 v1 到 v2 迁移与旧项目回归测试。
- **交付物**：领域模型、数据库迁移、存储与回放测试。
- **预计时间**：1.5～2 个工作日。

### 阶段 2：多组计算与均值

**目标**：实现三组独立重算、顶部聚合统计和平均曲线。

- [ ] 增加固定三组计算调度和复合结果索引。
- [ ] 聚合最多 24 份样本的顶部统计。
- [ ] 实现相对时间重采样、平均 RSSI 曲线和均值结果。
- [ ] 增加缓存和性能测试。
- **交付物**：多组分析服务、均值服务、统计与性能测试。
- **预计时间**：1.5～2 个工作日。

### 阶段 3：采集与界面

**目标**：完成无组管理负担的采集流程和独立图表切换。

- [ ] 实现最小空位优先、满组覆盖第三组和成功后原子替换。
- [ ] 增加默认步速和本次步速交互。
- [ ] 增加每图四状态切换、最近组默认选择和删除。
- [ ] 接入均值曲线、只读均值指标和全组统计明细。
- **交付物**：可操作的完整桌面流程和 UI 自动化检查。
- **预计时间**：2～2.5 个工作日。
