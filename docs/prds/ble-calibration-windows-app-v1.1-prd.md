## 1. 为什么要做

当前 BLE 数字钥匙标定主要依赖测试人员在多个方向反复行走、观察日志并手工判断：

- 哪个节点首先满足解锁或闭锁条件。
- 条件满足时 5 节点的瞬时 RSSI。
- RSSI 距离当前阈值的差值。
- 条件满足前后的 RSSI 序列和变化率。
- 调整某个阈值或附加策略后，多个方向会受到什么影响。

目标是把一次八方向测试沉淀为可重复分析的数据，使测试人员能够在一次采集后反复进行
What-if 重算，减少实车反复行走次数。

首版成功指标：

- 一次完成的方向采集能够被反复调整参数并重算，无需为每组参数重新行走。
- 修改任一阈值或策略后，8 个方向在 200 ms 内完成重算。
- 相同原始数据、参数和计算版本产生完全一致的结果。
- Windows 安装包在未安装 Python 的 Windows 10/11 64 位电脑上可以运行。
- 最终实车阶段连续采集 2 小时无崩溃。

## 2. 是否存在更简单的首版

首版采用以下最小闭环：

1. 使用 Mock CAN 或历史数据完成开发和自动化测试。
2. 测试人员手动选择方向并开始/结束记录。
3. 测试人员手动输入解锁和闭锁距离。
4. 应用只读 CAN，不向车辆发送或刷写配置。
5. 支持云推参数解码、What-if 修改和编码导出。
6. 不在首版实现自动测距和自动推荐最终阈值。

该范围能够验证核心价值，同时避免传感器测距、车辆写入和自动优化算法扩大首版风险。

## 3. 目标用户

主要用户：

- 数字钥匙 BLE 标定工程师。
- 实车测试人员。

次要用户：

- 负责策略验证和问题分析的软件工程师。
- 需要回看测试结果的项目成员。

## 4. 使用场景

### 4.1 开发阶段

1. 生成一组确定性的八方向 Mock CAN 数据。
2. 应用使用 Mock 数据源或离线回放读取数据。
3. 验证报文解码、方向会话、策略计算、图表和项目保存。
4. 修改相同随机种子后应得到相同结果。

### 4.2 实车阶段

1. 测试人员连接 ZLG USBCANFD-200U。
2. 解码当前云推 HEX，得到基础阈值和附加策略。
3. 选择一个测试方向并开始录制。
4. 测试人员携带钥匙远离车辆，等待闭锁。
5. 测试人员转身靠近车辆，等待解锁。
6. 输入本方向实际闭锁、解锁距离。
7. 完成该方向，重复直至最多 8 个方向完成。
8. 调整 What-if 参数，查看 8 个方向联动结果。
9. 编码修改后的云推 HEX并保存项目。

### 4.3 离线分析

1. 打开已保存项目或导入历史 BLF。
2. 查看原始 RSSI、实车请求和方向元数据。
3. 修改阈值或策略并重新计算。
4. 恢复到本次解码的原始参数。

## 5. 已确认的功能需求

### FR-001 Windows 桌面应用

- 应用最终以 Windows EXE/安装包交付。
- 用户电脑不需要安装 Python。

### FR-002 五节点 RSSI

节点顺序固定为：

1. 主节点。
2. 前节点。
3. 后节点。
4. 左节点。
5. 右节点。

### FR-003 八方向

最多记录以下 8 个方向：

1. 正前。
2. 右前。
3. 正右。
4. 右后。
5. 正后。
6. 左后。
7. 正左。
8. 左前。

### FR-004 CAN 数据来源

- `0x629`：主节点 RSSI。
- `0x62A`：前、后节点 RSSI。
- `0x62B`：左、右节点 RSSI。
- `0x55A`：解锁、闭锁请求。
- 实车和 Mock 必须使用同一套字节解码逻辑。

### FR-005 原始数据保留

- 原始 CAN 数据可保存为 BLF。
- 测试项目保存方向、距离、步速、云推参数和计算结果。
- 原始 CAN 数据与 What-if 派生结果分离。

### FR-006 基础闭锁规则

- 有效节点全部进入闭锁区并持续 2 秒后产生闭锁动作。
- 阈值配置为 `0` 的节点不参与闭锁判定。
- 条件开始持续满足、开始计时的时刻为实线。
- 持续 2 秒完成后的闭锁动作时刻为虚线。

### FR-007 基础解锁规则

- 任一有效节点进入解锁区并持续 0.5 秒后产生解锁动作。
- 阈值配置为 `0` 的节点不参与解锁判定。
- 条件开始持续满足、开始计时的时刻为实线。
- 持续 0.5 秒完成后的解锁动作时刻为虚线。

### FR-008 附加策略

以下策略修改后必须动态重算 8 个方向：

- 主节点单独解锁 `mstUnlock`。
- 快速闭锁 `quickLock`。
- 快速解锁 `quickUnlock`。
- 主节点强于从节点 `mstThanSlave`。
- 斜角度补偿解锁 `bevelAngle`。

### FR-009 条件时刻信息

实线对应条件开始持续满足的时刻。以下信息均取实线时刻：

- 触发节点。
- 5 节点瞬时 RSSI。
- 实线旁文字，例如 `闭(主)`、`解(前)`。

### FR-010 动作时刻信息

- 虚线对应解闭锁动作时刻。
- 使用原始参数查看实测数据时，`0x55A` 的解闭锁请求是实际动作和距离的时间锚点。
- 进入 What-if 后，虚线是当前参数计算出的动作时刻。
- 修改基础阈值或附加策略后，实线和虚线都必须重新计算。
- 原始 `0x55A` 事件始终保存在项目数据中，但图上不额外叠加“实测/What-if”第三种标线。
- 每个方向标题显示实际触发的策略。

### FR-011 距离

- 测试人员手动输入实际闭锁距离和实际解锁距离。
- 两个实际距离分别绑定对应 `0x55A` 虚线实际动作时刻。
- 实际距离是原始参数下的距离锚点；原始参数下的计算距离等于输入的实际距离。
- What-if 虚线移动后，应用根据新旧虚线的时间差和步速计算当前动作距离：

```text
闭锁当前距离 = 实际闭锁距离 + 步速 × (What-if 闭锁时刻 - 实测闭锁时刻)
解锁当前距离 = 实际解锁距离 - 步速 × (What-if 解锁时刻 - 实测解锁时刻)
```

- 图表距离背景、方向评级和优良差汇总均使用当前计算距离。

### FR-012 距离等级

闭锁：

- 优：`8 <= 距离 <= 12` m。
- 良：`5 <= 距离 < 8` m 或 `12 < 距离 <= 16` m。
- 差：`距离 < 5` m 或 `距离 > 16` m。

解锁：

- 优：`2 <= 距离 <= 5` m。
- 良：`0.5 <= 距离 < 2` m 或 `5 < 距离 <= 8` m。
- 差：`距离 < 0.5` m 或 `距离 > 8` m。

### FR-013 图表

- 每个方向一个 RSSI 变化图。
- 最多 8 个图纵向排列。
- 5 节点曲线同图显示。
- 横轴为时间，默认 2 秒一个刻度。
- 图表使用尽可能大的页面宽度和足够的高度。
- 图下方显示距离输入和条件瞬时 RSSI。

### FR-014 参数面板

- What-if 参数在页面顶部。
- 参数面板支持隐藏和显示。
- 隐藏后在页面下方仍可以快速重新显示。
- 一键还原恢复到本次解码时的参数。

### FR-015 云推 HEX

- 支持从 HEX 解码基础阈值和附加策略。
- 支持编辑已存在字段并编码回原数据。
- 未识别字节和未修改字段保持不变。
- 编码结果可以被 `tools/parse_cloud.py` 再次解析。

### FR-016 统计

- 显示闭锁优秀率和解锁优秀率。
- 列出评级为良的方向。
- 列出评级为差的方向。
- 原始参数下，优良差评级使用测试人员输入的实际解闭锁距离。
- What-if 参数变化后，使用新虚线时刻对应的当前计算距离重新评级。
- 8 个方向的优秀率、良方向列表和差方向列表必须同步重算。
- 闭锁优秀率的分母为已输入实际闭锁距离的方向数。
- 解锁优秀率的分母为已输入实际解锁距离的方向数。
- 当前参数没有计算出对应动作的方向仍计入分母，并列入 `差（未触发）`。
- 分母为零时显示 `--`，不显示 `0%`。

### FR-017 Mock 优先

- Windows 打包完成前，开发和自动化测试不依赖 CAN 盒或实车。
- Mock 提供原始 CAN 帧，而不是直接提供已经解码的业务数据。
- Mock 支持确定性随机种子。
- 打包完成后再进行 CAN 盒和实车联调。

## 6. 非功能需求

### NFR-001 性能

- 修改任一参数后，8 个方向的重算目标时间不超过 200 ms。
- CAN 接收线程不能因 UI 绘制或策略重算阻塞。
- UI 绘制应限帧，策略计算使用完整时间序列。

### NFR-002 可重复性

- 相同输入数据、参数和计算版本必须产生相同结果。
- 项目重开后的结果必须与保存前一致。

### NFR-003 可诊断性

- 记录设备连接、断线、解码错误、节点过期、保存失败和策略计算异常。
- 错误信息应包含时间、方向和可定位的错误原因。

### NFR-004 数据安全

- 首版只读 CAN。
- 不允许在未明确确认的情况下向车辆发送报文或写入云推参数。

### NFR-005 兼容性

- 支持 Windows 10/11 64 位，不支持 Windows 7 和 32 位系统。
- CAN 软件依赖基线为 `python-can==4.6.1`、`zlgcan==0.3.0`。
- `clgcan_driver` 原生 `.pyd` 由 `zlgcan` 包提供。
- 正式版本需要在未安装 Python 的干净系统验收。

## 8. 已冻结的高影响决策

### D-001 实车事件基准：已确认

`0x55A` 中：

- `1` 代表实际解锁动作请求。
- `2` 代表实际闭锁动作请求。
- 两个信号作为实测动作和距离锚点。

### D-002 Windows 与 ZLG 运行环境：已确认

- 仅支持 Windows 10/11 64 位。
- `python-can==4.6.1`。
- `zlgcan==0.3.0`。
- `clgcan_driver` 为 `zlgcan` 包自带 `.pyd`。
- `tools/can_read_save.py` 已在目标 Windows 电脑上验证可以读取 RSSI 和解闭锁数据。
- 具体 ZLG 系统驱动版本不阻塞软件开发，在最终实车安装矩阵中记录并验证。

### D-003 单方向完成与距离锚点：已确认

- 两个实际距离分别对应虚线实际闭锁、解锁时刻。
- 实线表示策略条件开始持续满足的时刻。
- 闭锁和解锁事件齐全时方向自动完成。
- 缺少任一事件时，测试人员可以手动结束并保存为“不完整方向”。

## 13. 设计决策与风险

主要设计决策：

- CAN、Mock 和离线回放共用同一套原始帧解码接口。
- CAN 接收与 UI/策略计算隔离，避免绘图阻塞采集。
- 原始 CAN 数据只追加；What-if 只更新派生结果。
- 首版采用 standalone/onedir 打包，降低 Qt 插件和原生 `.pyd` 路径风险。

主要风险及应对：

| 风险 | 应对 |
| --- | --- |
| `clgcan_driver.pyd` 与打包 Python ABI 不兼容 | 第二步在目标 Windows 记录 `python -VV` 和 `.pyd` 文件名，锁定构建版本 |
| 三类 RSSI 报文不同步 | 保存节点时间戳、age 和 stale 状态，使用时间差而不是样本数判定 |
| What-if 与 ECU 实际策略存在偏差 | 最终实车阶段使用 `0x55A` 逐方向建立黄金对比用例 |
| 原始数据与派生数据混用 | 项目模型分离原始帧、会话输入、参数和计算结果 |
